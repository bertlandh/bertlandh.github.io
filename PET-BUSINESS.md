## Repository inspection and architecture
Production source is the independent bertlandh.github.io Git repository, not its
parent Website project. Native Windows Ruby/Jekyll, existing Gemfile.lock and
remote theme remain in place. Existing /demos/ sites are unrelated.

- /pets/: homepage, catalogue, about, care, contact, privacy and buying information.
- /pets/assets/: isolated styles, script, mark and optimized editorial image.
- /_data/pet_business.yml: identity, base path, launch state and contacts.
- /_pet_listings/: individual Markdown records, generated by Jekyll collection.
- /_layouts/pet.html and pet-product.html: own full HTML document; no parent
  LearnTech layouts, navigation, footer, SEO plugin or tracking snippets.
- /_includes/pet-card.html and pet-enquiry.html: scoped components.

Only the pet_listings collection is added to the shared _config.yml. No existing
routes, layouts or theme settings are replaced. PET-BUSINESS.md must be excluded
from deployment. All PrettiPetz pages have sitemap:false while preparing to open.
Noindex follows the global launch_ready flag. Robots must allow crawling so that
search engines can read noindex; a nested robots.txt would not control /pets/.
No noindex setting is a privacy/access-control mechanism. Do not upload confidential
business information into this source or public assets.

## Inventory workflow
1. Copy the unpublished listing-template.md to a descriptive new filename.
2. Keep published:false and verified:false while gathering information.
3. Fill title, category (birds/eggs/supplies), species, unique reference,
   summary, numeric price_jmd and price_unit. Price must be verified, not guessed.
4. Availability must be available, reserved or unavailable. Reserved is not a
   promise of supply; WhatsApp only asks about status. Unavailable has no order CTA.
5. Add photos of the ACTUAL item/animal with accurate alt text. Put local assets
   in pets/assets/inventory/. Strip location metadata and optimize WebP/JPEG;
   keep originals elsewhere. Do not use editorial images as listing photos.
6. Complete care, sourcing, permit_information and collection_information.
   For eggs also complete egg_information: purpose, dates, storage and handling;
   do not imply guaranteed fertility or hatching. Verify species/legal status
   and necessary documentation before offering animals or eggs.
7. Have the animal-care partner approve every factual claim and image.
8. Set verified:true and published:true only after validation. Set sitemap:true
   only for approved listings when the business is ready for indexing.
9. Build and inspect the generated page, catalogue filters and WhatsApp message.
10. When stock changes, update availability promptly and rebuild. Never delete
    a sold listing without deciding whether to retain it unavailable or redirect it.

No example price, animal, testimonial or credential is published. The collection
template is deliberately excluded from the built site. Actual detail pages become
available when a verified listing is published; there are no fictitious products.

## Contacts and WhatsApp
Set whatsapp to the confirmed international number using digits only (no +,
spaces or dashes). Confirm it belongs to PrettiPetz, not the hosting organisation.
Set location, collection_details, hours and optional email/phone_display.
The WhatsApp link encodes the title and reference; the customer sends the message.
No form/backend stores customer data and no payment is taken by this website.
Do not enable a CTA until the owner confirms the number works in WhatsApp.

## Launch checklist — outstanding
- Owner-approved business identity and logo; the simple illustrated mark is a
  new working brand asset, not an assertion of an established registered brand.
- Confirm WhatsApp, location/service area, opening/contact hours and collection.
- Supply real inventory, prices/units and actual photos with usage rights.
- Verify lawful sourcing, species requirements and any permits/documentation.
- Approve payment/deposit, refund/cancellation, collection and after-sales terms.
- Complete privacy details for order records/contact/retention before orders.
  Set policies_approved:true only once these policies are approved and published.
- Replace or approve editorial photo use and social-share image.
- After completing the checklist and enabling the opening/index settings, run
  bundle exec ruby scripts/check-pet-business.rb --launch; resolve every blocker.
- Set launch_ready:true; change approved page front matter sitemap:false to true;
  publish collection entries sitemap:true and verify generated sitemap/canonicals.
- Test real WhatsApp on phone; verify totals, images, filters and keyboard access.
- Deploy through the existing GitHub Pages workflow only with owner authorization.
- Confirm live pages and submit the sitemap after launch; do not promise rankings.

## Analytics readiness
No analytics is loaded and existing LearnTech GA configuration is not inherited.
The script emits prettipetz:enquiry-click with page path only. A future integration
can listen AFTER valid consent. Do not send search text, phone numbers, names or
WhatsApp message contents to analytics. Review consent and privacy content before
adding an approved property. An enquiry click is not a confirmed sale/enquiry.

## Domain migration
Copy pets/, scoped layouts/includes, data and collection into the new Jekyll site.
Set site.url to the new HTTPS origin, site.baseurl as required, pet_business
base_path to an empty string, and public_origin to the new origin or leave empty.
Move pets' page directories/assets to the new site root. Change collection
permalink from /pets/catalogue/:name/ to /catalogue/:name/ and update photo srcs.
No host branding or domain is embedded in the customer layout. Check canonical,
OG image and internal URLs in output; set DNS/CNAME only when the domain is approved.
Arrange permanent redirects from the old location where the host permits them.

## Local preview (existing Windows toolchain)
From the parent Website folder, use scripts/local-build.ps1 with the existing
RubyHome and GemCache documented in project-docs/local-build.md. Add -Serve
-Port 4126, then open http://127.0.0.1:4126/pets/. Stop the owned preview with
Ctrl+C when finished. No WSL or new framework installation is needed.

From the production source folder, after building:
  bundle exec ruby scripts/check-pet-business.rb
The check reports outstanding launch blockers without treating the prelaunch
state as an error. After completing launch setup, add --launch to require them
all to be resolved. The bundle and Ruby paths must be configured as in the
existing native Windows build guide.

## PrettiPetz SEO — 19 November 2026
On-page preparation covers sixteen HTML pages: the original thirteen plus birds,
quail-egg enquiries and cages. These are substantive category pages with distinct
copy, relevant internal links and confirmed enquiry information, not town clones.

Metadata source: _data/pet_seo.yml. Output: _includes/pet-seo.html in the isolated
pet layout. Each page has a unique title/description, canonical URL, OG/Twitter
sharing metadata and language information. Future listings can supply seo_title
and seo_description in front matter; otherwise listing title/summary are used.
The repeatable audit fails duplicate titles/descriptions, malformed JSON-LD,
missing image descriptions/dimensions and incorrect indexing gates.

Target intent:
- Homepage: birds, pets and cages in Jamaica / PrettiPetz.
- Birds: pet birds in Jamaica; lovebird and budgie enquiries; related pair guides.
- Eggs: quail egg enquiries in Jamaica; handling and collection questions.
- Cages: bird cages / pet housing in Jamaica; actual supplied cage photos.
- Pair guides: diamond dove, button quail and zebra finch pair prices in Jamaica.
- About and contact cards: PrettiPetz, Bertland Hope and Krishna Baddaloo.
No meta-keyword stuffing, hidden keyword text or invented place names is used.

Structured data links Organization, WebSite, Person, ProfilePage, WebPage,
CollectionPage/ImageGallery and appropriate breadcrumbs. Gallery ImageObjects
use the actual image URLs and dimensions. Price enquiries do not pretend to be
verified purchasable stock: no Product offers, stock schema or review ratings.
No LocalBusiness/PetStore address, coordinates, map profile or opening hours are
invented. Pickup is at an agreed meeting point; town and parish remain unknown.
No VideoObject upload date is invented for footage that has not been published.

Images retain descriptive filenames and now have observational alt descriptions,
visible captions, intrinsic dimensions and lazy loading except the priority hero.
Full-size images remain available; eleven responsive thumbnails total 669,266
bytes and are supplied through srcset/sizes. Source metadata remains stripped.
The image sitemap lists the full-size gallery images only after launch readiness;
verified, index-approved future inventory photos are supported too. Responsive
variants need not be separate entries for the same underlying photo.

Before launch: launch_ready remains false; all sixteen pages emit noindex;
/pets/image-sitemap.xml has zero image entries; the root robots.txt does not
advertise that sitemap. Existing LearnTech sitemap/robots lines remain intact.
Robots allows crawling so crawlers can read noindex. This is not access control;
never place confidential information in public assets. Google indexing/rankings
and removal of already-indexed URLs cannot be guaranteed by markup alone.

After verified content and policies are ready:
1. Confirm current stock/photos, public location/service information, contact
   hours and collection/buying policies. No walk-in address is currently supplied.
2. Approve sitemap:true on the pages/listings that should be indexed; then enable
   launch_ready only as an intentional release. Rebuild and run both audits.
3. Confirm the actual live output, sitemap and canonical URLs; submit the sitemap
   through authorized Google Search Console and Bing Webmaster Tools access.
4. Inspect representative URLs and image discovery, then measure impressions,
   clicks and relevant enquiries over time. Do not claim instant broad rankings.
5. Evaluate a separate PrettiPetz Google Business Profile only after confirming
   the actual eligible in-person operating model and verification details. An
   agreed pickup point is not a permanent staffed storefront address. Never
   rename or reuse LearnTech's separate listing for this business.

Google supports its search-result site-name feature at domain/subdomain level,
not the /pets/ subdirectory. The pages may be indexed after release, but a
separate displayed PrettiPetz site name cannot be promised on this shared domain.
A future dedicated domain, as already planned, supports independent identity.
On migration also update pet_seo.yml route keys, pet_media.yml asset prefixes,
image-sitemap/robots paths and the audit's site prefix, alongside the existing
base_path, collection routes and canonical-origin instructions.
